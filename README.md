# 峻熹的学习笔记

顾峻熹（GitHub: [Foolscape](https://github.com/Foolscape)，昵称 Junxiii）的学习笔记站。

线上地址：**<https://foolscape.github.io/>**

用 [VitePress](https://vitepress.dev/) 构建，笔记写 Markdown，手写扫描件与课件以 PDF 归档，按**学期 → 课程**两级组织。推送到 `main` 分支后由 GitHub Actions 自动构建并发布。

## 一、日常怎么用（最常用的三条）

### 1. 写一篇新笔记

在对应课程文件夹下新建 `.md` 文件即可，**不用改任何配置**：

```text
docs/专业课/大二秋冬/电路与电子技术I/第01章-电路基本概念.md
```

侧边栏会在下次构建时自动出现这一条，标题取文件里第一个 `# 一级标题`。

### 2. 上传一份 PDF / 扫描件

丢进对应课程的资料文件夹：

```text
docs/public/资料/大二秋冬/电路与电子技术I/第01章课件.pdf
```

构建时会自动把文件列成**一张紧凑列表**（文件名、类型、大小），直接长在对应课程页的末尾。

**点文件名就能在本页预览**，再点一次收起。列表下面只有**一个共享的预览区** —— 不管这门课有 1 份还是 30 份资料，都不会堆出一排方框。

> **为什么不是一个文件一个预览条**：一学期攒下十几份作业 PDF，页面上就会出现十几个长得一模一样的带按钮方框，又长又难找。改成「列表 + 共享预览区」之后，页面长度只跟文件行数相关。
>
> 预览区**默认不加载**，点开才拉 PDF —— 一进页面就自动下载十几 MB 会很卡。
>
> 手机浏览器可能不支持内嵌 PDF，所以每行都配了「打开」和「下载」的真实链接，关掉 JS 也能用。列表本身是服务端渲染进 HTML 的，**本地搜索能搜到文件名**。
>
> 这套由 `scripts/build-index.mjs` 自动生成（组件：`docs/.vitepress/theme/components/MaterialList.vue`），不用手写。

**想在某一篇笔记里嵌单个 PDF**（比如把作业原卷放在对应章节旁边），用 `PdfViewer` 组件 —— 也已全局注册：

```markdown
<PdfViewer src="/资料/大一春夏/常微分方程/ode笔记.pdf" />
<PdfViewer src="/资料/xxx.pdf" title="期中真题" height="600px" open />
```

| 属性 | 默认值 | 说明 |
| --- | --- | --- |
| `src` | 必填 | PDF 路径，通常以 `/资料/` 开头 |
| `title` | 用文件名 | 显示名 |
| `height` | `78vh` | 展开后的高度 |
| `open` | `false` | 是否默认展开 |

> 源码在 `docs/.vitepress/theme/components/PdfViewer.vue`。

#### PDF 太大怎么办？

手写笔记用触控笔导出时，每一笔都是**矢量路径**、坐标还精确到小数点后 6 位 —— 一页能有 7 万条绘图指令，所以体积会大得离谱（实测一份 52 页的笔记导出成 21.96 MB）。

**先记住一个实测结论：对这类手写笔记，栅格化并不能做到「又小又清晰」。** 别指望压到几 MB 还看不出差别。

##### 实测数据（同一份 52 页笔记）

| 做法 | 大小 | 文件数 | 画质 |
| --- | --- | --- | --- |
| 矢量原版 | 21.96 MB | 1 | 完美，无限放大 |
| **原栅格导出（当前采用）** | **8.25 MB** | **1** | **可接受** |
| 矢量按 3 章拆分 | 5.40 / 10.11 / 6.44 MB | 3 | 完美 |
| 矢量按 8 页拆 7 块 | 约 3～4 MB / 块 | 7 | 完美 |
| PNG 无损 150 DPI | 7.67 MB | 1 | 无压缩伪影，但有 150 DPI 上限 |
| PNG 无损 200 DPI | 10.87 MB | 1 | 无压缩伪影，但有 200 DPI 上限 |
| JPEG 200 DPI / q85 | 9.22 MB | 1 | 好，有轻微伪影 |
| JPEG 300 DPI / q88 | 17.40 MB | 1 | 更好，体积接近原版 |

**结论**：单文件 + 可接受画质，8.25 MB 那版已经接近最优。想再快，唯一的办法是**拆分**（牺牲文件数，换来每次只加载一部分且零失真）。

##### 工具一：无损拆分（画质与原文件完全一致）

```bash
npm run pdf:split -- "_原始文件/原版.pdf" "docs/public/资料/大一春夏/常微分方程" "ode笔记" 1-15 16-37 38-52
```

页码 1 起、含两端，自动补零对齐。矢量内容原样搬运，**零失真**。切得越细单次加载越快，代价是文件变多。

##### 工具二：栅格化压缩（有损，慎用）

```bash
npm run pdf:shrink -- "笔记.pdf" --dpi=200 --quality=85
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--dpi=N` | 150 | 渲染精度。**这是画质关键**，细笔画发虚、放大像马赛克就是它不够 |
| `--quality=N` | 70 | JPEG 质量 **0–100**。笔画周围有块状噪点就是它太低 |
| `--format=png` | jpeg | 改无损 PNG，没有块状噪点但体积大得多 |
| `--gray` | 关 | 转灰度（有彩色笔迹别开） |
| `--pages=a-b` | 全部 | 只处理部分页，用来试参数 |
| `--jpg=N:文件` | — | 只把第 N 页导成 JPG，方便肉眼对比画质 |

> ⚠️ **踩过的坑（务必保留）**：`@napi-rs/canvas` 的 `toBuffer('image/jpeg', q)` 里 **q 是 0–100**，不是浏览器 Canvas 那种 0–1。传 0–1 会被**静默钳到最低画质、且不报错**，看起来像是"压缩率极高"，实际全是 JPEG 噪点。脚本里已经封装成 `encode()` 处理好了。

> 两个工具都不会修改原文件。大体积原件放 `_原始文件/`（已在 `.gitignore` 里），只留本地，不提交、不部署。

### 3. 新增一门课 / 一个学期

只要建立文件夹就行，两边哪个先建都可以：

```text
docs/专业课/大二秋冬/操作系统/              ← 笔记
docs/public/资料/大二秋冬/操作系统/          ← 资料（只放 PDF 也会自动建课）
docs/专业课/大二春夏/                        ← 新学期，建个文件夹即可
```

课程总览页 `index.md`、学期总览页 `index.md` 如果不存在都会自动生成。顶栏「专业课」下拉菜单、左侧目录同步自动更新。

> **删除课程**：把文件夹删掉即可，剩下的引用会自动消失。

## 三、发布到线上

```bash
git add .
git commit -m "新增：数据结构第三章笔记"
git push
```

推送后 GitHub Actions 会自动跑（约 1～2 分钟），到仓库的 **Actions** 标签页能看到进度，跑完访问 <https://foolscape.github.io/> 就是最新的。

### ⚠️ 首次需要手动改一次设置

Pages 现在是「从分支部署」模式，要改成「从 Actions 部署」：

1. 打开 <https://github.com/Foolscape/Foolscape.github.io/settings/pages>
2. **Build and deployment → Source** 选 **GitHub Actions**
3. 回到 <https://github.com/Foolscape/Foolscape.github.io/actions>，手动跑一次 `Deploy notes site to GitHub Pages`（点进去 → `Run workflow`）

改完之后，以后每次 push 都会自动发布，再也不用管。

> **根目录的旧 `index.html` 已删除。** 它是建站初期的手写占位页；2026-09-17 的 GitHub Actions 部署验证成功后，线上服务的就是构建产物，它已经没有作用了。万一哪天想找回来：
>

> **文件列表是并入课程页的，没有独立的「资料下载」页。** 某门课在 `docs/public/资料/<学期>/<课程>/` 下有文件时，列表会自动出现在该课程页末尾；没有文件就什么都不显示。文件删光时列表也会自动消失。
>
> 列表用注释标记包起来，长这样：
>
> ```markdown
> <!-- 资料列表：开始（自动生成，勿手改这一段） -->
> ## 资料文件
> | 文件 | 类型 | 大小 |
> ...
> <!-- 资料列表：结束 -->
> ```
>
> 标记之间的内容每次构建都会被覆盖，**别手改**；但整段可以**拖到页面任意位置**，位置会被保留。想引用它，用 `[资料文件](#资料文件)`。

| 类型 | 规则 | 例子 |
| --- | --- | --- |
| 章节笔记 | `第NN章-标题.md`（**N 补零**，顺序才稳） | `第03章-正弦稳态电路.md` |

排序规则：

- **学期**按 大一秋冬 → 大一春夏 → 大二秋冬 → …… 排列（认不出的名字排最后按拼音）
- **每门课内**：`index.md` 永远最前，其余按中文数字序（资料列表已并入 `index.md`，不再有独立页面）

## 六、常见问题

**PDF 能直接放仓库吗？多大合适？**

能。单个文件 GitHub 限制 100MB，仓库建议控制在 1GB 以内（超过会收到警告）。手写扫描件建议先压缩：拍照的用图片压缩工具，多页的合成一个 PDF 再上传。课程页的资料表格会显示每个文件的大小，方便你盯着。

**中文文件名会不会出问题？**

不会。URL 会被自动编码，浏览器、GitHub Pages 都正常处理。唯一要注意的是别用 `%`、`#`、`?` 这类在 URL 里有特殊含义的符号。

**笔记里的公式怎么写？**

**已经配好了，直接用。** 行内公式用单个 `$`，独立成行的公式用两个 `$`：

```markdown
当 $a \ne 0$ 时，方程 $ax^2 + bx + c = 0$ 有两个解。

$$
x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
$$
```

渲染用的是 MathJax（`markdown-it-mathjax3`），在**构建时**就转成了内联 SVG，所以：

- 页面打开**不需要额外下载 JS**，也不依赖 CDN，离线可用
- 缺点是一页公式很多时 HTML 会变大（一个公式约十几 KB），但 gzip 压缩率约 7:1 —— 实测含 8 个公式的页面 gzip 后 21 KB，可接受

> **配置里有个必须保留的坑**：MathJax 输出的 `<mjx-container>` 是自定义标签，必须通过 `vue.template.compilerOptions.isCustomElement` 告诉 Vue 别当组件解析，否则**整块公式会静默变成空占位 `<!---->`**（页面不报错，但公式就是不显示）。这一项在 `config.mts` 里，别删。
>
> 如果哪天觉得体积太大，可以换成 KaTeX（HTML 输出小得多，代价是要额外加载 CSS 和字体）。

**能不能直接在网上改笔记？**

可以。在 GitHub 上打开 `docs/专业课/.../某章.md`，点铅笔图标改完提交，网站会自动更新。手机上也能改，适合上课随手记一句。

**`npm install` 报 `EPERM` 怎么办？**

普通终端里不会遇到。如果是在受限环境（受管终端、沙箱）里，通常是两个原因：写不了系统缓存目录，或者禁止子进程管道（`esbuild` 的 postinstall 要 spawn 进程）。这样绕过：

```bash
npm install --cache ./.npm-cache --ignore-scripts
```

`--ignore-scripts` 在这里是安全的：esbuild 的可执行文件由 `@esbuild/win32-x64` 这个可选依赖直接提供，postinstall 只做版本校验，跳过它不影响构建和预览。

**为什么仓库名不能改成 Junxiii？**

GitHub Pages 的用户主页要求仓库**严格命名**为 `<用户名>.github.io`，这样才能拿到 `https://foolscape.github.io/` 这个根域名。改名后网址会变成 `https://foolscape.github.io/Junxiii/`，多一层路径，不划算。`Junxiii` 这个名字保留在 GitHub 的**昵称（Name）**字段里，个人主页上照样大字显示。
